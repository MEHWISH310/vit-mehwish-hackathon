# Live demo run-of-show (target 4:30, hard limit 5:00)

The problem statement caps the live demo at 5 minutes, so this script is timed to 4:30 with 30 s of slack. The same flow works for the recorded video: the guidelines suggest about 10 minutes, but a tight 5-minute recording satisfies both.

**Before you start (not on the clock)**
- `pip install -r requirements.txt` and `python -m src.engine.pipeline` already run once; `streamlit run app.py` open in a browser at 100% zoom, on the "Engine signals" tab, sidebar at defaults.
- A terminal open in the repo root with the font enlarged.
- Close notifications. Have `docs/presentation.pdf` open in another window in case you need a slide.

| Time | Screen | What to do | What to say |
|---|---|---|---|
| 0:00-0:30 | Slide 1 or README top | - | "Market-moving information arrives as text: news and social posts. I built one NLP Risk Engine that turns each text into a sentiment score, an event type and an impact score, then two modules that act on them: a sentiment-tilted index and an event-triggered stress test of a banking portfolio. All data is synthetic." |
| 0:30-1:00 | Terminal | Run `python -m src.engine.pipeline` (about 5 s), then `python -m pytest -q tests` | "Two sources, 1,212 news and 2,762 social posts, go into one schema; the engine trains and scores every text out-of-fold and writes signals to file, a REST API and a pub/sub bus. 27 tests pass." |
| 1:00-1:50 | Tab **Engine signals** | Point at the event-type bars, then scroll to **Try it live**. The box is pre-filled with `Goldman Sachs warns of covenant breach as losses mount, a major shock for credit markets`: click **Analyze** (expect GS, sentiment -0.72, Credit Event, impact 7.8, "would TRIGGER"). Then paste `Moody's downgrades Goldman Sachs to junk as trading losses mount` and click **Analyze** again (Credit Event, impact 5.9, "would not trigger"). | "Negative sentiment, Credit Event, linked to GS, impact 7.8, so Module B would run a stress test. A plain downgrade scores 5.9 and does not. On 20 hand-written texts the models never saw, event accuracy is 0.90 and sentiment correlation 0.88. The synthetic-data scores are higher, but that is the optimistic number." |
| 1:50-2:50 | Tab **Module A** | Point at the metric cards, the stacked weights, the NAV chart and the heatmap. Scroll to **Latest weight changes and why** and read the top row's driver. Move **Sentiment tilt** to 0 in the sidebar: NAV collapses onto the benchmark. Set it back to 1.5. | "Each stock's score is impact- and source-weighted sentiment with a 36-hour half-life. Positive sentiment raises the weight, negative lowers it, bounded between 2 and 15 percent with at most 20 percent turnover a day, and no look-ahead. +3.4% vs -6.8% for equal weight, and a shuffled-sentiment placebo does no better than the benchmark. Caveat: synthetic prices came from the same events, so this proves the plumbing, not alpha." |
| 2:50-4:00 | Tab **Module B** | Point at "248 stress tests triggered". The selector defaults to the worst event: read the headline, then the waterfall and P&L by asset type. Filter event types to *Geopolitical* only and pick one. | "369 high-impact signals become 248 distinct stress tests, because I de-duplicate within 24 hours and only stress the adverse case. Worst: a Goldman covenant-breach headline, impact 10, costs 120 million, or 5.7%, of a 2.1 billion book. Loans and bonds lose on spreads, and the CDS protection we hold gains." |
| 4:00-4:30 | Module B, **Custom shock** | It opens on the brief's preset "equities -10%, rates +200bp": read -3.36%. Drag **Credit spread shock** to +200bp and show the loss grow. | "This is the brief's own scenario: minus 70 million, and the swaps and puts offset 78 million. Valuing derivatives on market value instead of notional would hide almost all of that hedge. The model is first-order, with no convexity or correlations, and that is the next step." |
| 4:30 | - | Stop. | "Code, data, deck and this run-of-show are in the repo. Thank you." |

**If something breaks:** if the dashboard says `outputs/signals.csv` is missing, run `python -m src.engine.pipeline` and refresh. If Streamlit is slow on first load, it is caching the backtest and stress runs; the second view is instant.
